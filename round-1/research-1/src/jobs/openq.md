## Open questions for iteration 2

These are the things this artifact could **not** settle. Each is phrased so iteration 2 knows what it is missing rather than discovering it mid-run.

1. **ProbGuard's exact requirement profile.** 2608.10621 [36] is the closest competitor on "cross-family calibrated safety risk from logits, no parent". Its abstract says training *"requires Monte Carlo-sampled completions to build calibration targets"* while deployment reads only the first ~10 decoding steps. **Unresolved: is the calibration model fitted per family or transferred?** If it transfers, it is a direct competitor on the primary endpoint and must be run, not cited. This is the single highest-priority remaining check — it is the R1 question all over again, one paper later.
2. **SelfGrader's anchor construction.** 2604.01473 [37] uses "PAC-guided in-context anchor examples". Unresolved: how many anchors, and are they fixed across models (which would make it input-anchored like ours) or refitted per model (which would make it a calibrated method)? Determines whether it is a baseline or related work.
3. **The full StrongREJECT judge prompt's stability across API providers.** The prompt is transcribed verbatim [11][12], but no commit hash was pinned. Iteration 2 should pin the commit and record it, since the repo is live.
4. **Whether `enable_thinking=False` actually repairs ORC.** 2609.18471 [30] localises the refusal-projection collapse at the *first generated token* for reasoning models. The empty `<think>\n\n</think>\n\n` pair moves the readout position but the next token is still the first *generated* token. **Unresolved whether the collapse persists after the empty pair.** This is checkable in ~10 minutes of forward passes and should be the first thing iteration 2 runs, because it decides whether Qwen3 — 80% of Chinese-origin abliteration targets — is usable at all.
5. **PLURIHARMS data availability.** [21] is the only prompt-level human-rated (≈interval) harm axis found, and no repository link appears in the proceedings PDF (grep for `github.com|huggingface.co`: 0 matches). Iteration 2 should email the authors or search a later release; it is the only path to a genuinely metric external severity axis.
6. **Kim & Han's five-family (LQMPG) aggregate.** Table 2's LQMPG column was truncated in the fetched HTML, so only the Gemma-excluded four-family figures (0.83 / 0.95) and Gemma's individual failure (0.16 ten-way, 0.74 AUROC) were recovered. The five-family aggregate is needed if the paper wants to quote a single number for the baseline.
7. **Spagliardi et al. 2026**, named in 2608.05086 as *"concurrent work applies adaptive testing to safety benchmarks"* [3], was not located. It is by construction another cheap-safety-evaluation competitor.
8. **Whether the ~15-forward-pass budget survives R14.** Robust dose-response design wants ~8–10 central levels plus replicated boundary levels [32]. Iteration 2 should decide the rung count and spacing **before** the run and report the design, not fit whatever it collected.
9. **Six name-regex terms remain unverified as live HuggingFace tags** (`neural-daredevil`, `no-refusal`, `unaligned`, `amoral`, `unfiltered`, `jailbroken`, plus `dpo-uncensored`, `de-censored`, `safety-stripped`). The cheap baseline is being implemented from a partially reconstructed list; this must be disclosed, and a 10-minute HF search closes it.
10. **Token-id-level BOS verification for OLMo-2 and StableLM-2** was inferred from `tokenizer_config.json` flags, not from an actual `encode()` call (no compute was available in this artifact). One `assert` at the top of iteration 2's harness closes it, and it should be an assert rather than a comment.
11. **The logit-gap phrase entries.** Four of the paper's 25 "refusal tokens" are multi-token phrases. The pre-registered resolution here is "first token of the phrase", but the original authors' intent is unknown and the paper does not say. Disclose the reconstruction; do not present the token set as fully verbatim-implementable.
